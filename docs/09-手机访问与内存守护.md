# 09 · 手机访问控制台 + 内存守护

> 控制台原本只监听 `127.0.0.1:3100`，靠 SSH 隧道访问。
> 这篇记录怎么做到手机浏览器直连，以及路上踩的三个坑。

## 一、反向代理方案

```
手机浏览器
   ↓ HTTPS 8443（Basic Auth）
nginx（自签证书）
   ↓ HTTP 127.0.0.1:3100
qq-bridge 控制台
```

### nginx 配置

```nginx
server {
    listen 8443 ssl;
    server_name _;

    ssl_certificate     /etc/nginx/ssl/qqbridge.crt;
    ssl_certificate_key /etc/nginx/ssl/qqbridge.key;
    ssl_protocols       TLSv1.2 TLSv1.3;

    auth_basic           "QQ Bridge";
    auth_basic_user_file /etc/nginx/qqbridge.htpasswd;

    location / {
        proxy_pass http://127.0.0.1:3100;
        proxy_http_version 1.1;

        # 桥接有 Host 白名单，只认 127.0.0.1:3100；改写成它才能通过
        proxy_set_header Host 127.0.0.1:3100;

        # 桥接会拒绝非回环 Origin（防 CSRF）；去掉它
        # （CSRF 仍由 application/json 要求 + 控制台令牌兜住）
        proxy_set_header Origin "";

        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_buffering off;
        proxy_read_timeout 600s;
    }
}
```

## 二、三个坑

### 坑 1 · Host 头校验（HTTP 403）

```
{"ok": false, "error": "Host 头不被允许（127.0.0.1）：控制台只接受本机回环访问"}
```

桥接的 DNS rebinding 硬化：

```js
const allowedHosts = [`127.0.0.1:${boundPort}`, `localhost:${boundPort}`, `[::1]:${boundPort}`];
if (!allowedHosts.includes(hostHeader.toLowerCase())) → 403
```

源码注释写着：**反代/端口转发场景会被一并拒绝 —— 这是有意的**。

**解法**：`proxy_set_header Host 127.0.0.1:3100;`

### 坑 2 · Origin 校验（POST 403）

页面能打开（GET），但一按保存就失败：

```
{"ok": false, "error": "跨站请求被拒绝"}
```

```js
if (req.method !== 'GET') {
  const origin = req.headers['origin'];
  if (origin && !allowedHosts.includes(new URL(origin).host)) → 403
}
```

浏览器发 POST 一定带 `Origin: https://47.98.87.62:8443` → 不在白名单 → 403。

**解法**：`proxy_set_header Origin "";`

**为什么这样仍安全**：桥接对 POST 还有两道硬要求 ——

1. `Content-Type: application/json`（跨站表单发不出来）
2. `x-console-token` 头（跨站拿不到）

再加 nginx Basic Auth，共三层。

### 坑 3 · `/api/roles/limit` 用空对象会把值写成默认

**这个坑导致了真实故障。**

测试时用 `-d '{}'` 调了 `/api/roles/limit`：

```
改之前:  闽越大王  7847 字符 → 注入 6000  ❌截断（被砍 1847 字）
```

**主卡最后 1847 字几个小时间没有注入。**

修法：

```bash
curl -X POST -H "x-console-token: $TOK" -H 'Content-Type: application/json' \
  -d '{"maxInjectChars":8000}' http://127.0.0.1:3100/api/roles/limit
```

**教训：这个接口对空 body 不报错，直接写默认值。**

## 三、内存守护

`/usr/local/bin/memguard`，systemd timer 每 5 分钟跑一次：

```bash
THRESHOLD_MB=280
COOLDOWN_MIN=30

AVAIL=$(awk '/MemAvailable/ {printf "%d", $2/1024}' /proc/meminfo)
SWAP_USED_PCT=$(( (SWAP_TOTAL - SWAP_FREE) * 100 / SWAP_TOTAL ))

# 可用 < 280MB 或 swap >= 60% 且不在冷却期 → systemctl restart dsh
```

```ini
# /etc/systemd/system/memguard.timer
[Timer]
OnBootSec=5min
OnUnitActiveSec=5min
AccuracySec=30s
```

日志：`sudo journalctl -u memguard -n 20`

输出形如：

```
[2026-11-20 21:39:45] 可用 676MB  swap 24%
[2026-11-20 21:39:45] 正常，无需动作
```

## 四、当前完整的访问入口

| 入口 | 地址 | 用途 |
|---|---|---|
| 本机 | `http://127.0.0.1:3100` | 服务器上直接访问 |
| SSH 隧道 | `ssh -L 3100:127.0.0.1:3100` | 电脑远程 |
| **手机** | `https://<公网IP>:8443` | Basic Auth + 令牌 |

需要在云服务器安全组放行 8443/TCP。
